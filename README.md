# NextAlerts apps

The NextAlerts dashboard as an installed app on Windows, Mac, Android and iPhone.

Every app is a thin shell around the live site **https://work.nextalerts.in**. Anything changed on the
website is in every app the moment it is deployed — no app update needed. The shell itself only changes
when this repo changes.

| Folder | App | Built with |
|---|---|---|
| `desktop/` | Windows `.exe`, Mac `.dmg` | Electron |
| `android/` | Android `.apk` | Native WebView (Java, Gradle) |
| `ios/` | iPhone / iPad | Swift + WKWebView (project generated by XcodeGen) |

## Ship a new version

```bash
node release.js 1.0.1
```

That commits, tags `v1.0.1` and pushes. GitHub Actions builds and tests every app and attaches the
installers to a release. Installed apps check the latest release and show an **Update app** button.

## What each shell adds

- Stays signed in, remembers window size (desktop).
- Links to other sites open in the normal browser.
- A "can't reach NextAlerts" screen that retries by itself.
- Downloads work (CSV exports, backups), also on Android where the page builds files in memory.
- Microphone for AI Voice, file uploads.
- Update from the GitHub release: Windows installs silently and reopens; Mac opens the new dmg;
  Android downloads the apk and starts the installer.

## iPhone

Without an Apple Developer signature: open work.nextalerts.in in Safari → Share → Add to Home Screen.

With an Apple Developer account, on a Mac:

```bash
cd ios && brew install xcodegen && xcodegen generate && open NextAlerts.xcodeproj
```

In Xcode: pick your Team under Signing & Capabilities, then Product → Archive → Distribute App
(TestFlight or App Store). The bundle id is `in.nextalerts.work`.

## Android signing key

The release key lives only in the repository secrets (`ANDROID_KEYSTORE_B64`,
`ANDROID_KEYSTORE_PASSWORD`) and in `_keys/` on the owner's PC (not in git). Keep that folder: an app
signed with a different key cannot update an installed one.
